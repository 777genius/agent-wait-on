# Exact implementation boundary

## Observation, not completion
Use the shared positional/reference wait loop. Do not change run/start/restart inline observation, status/list/delete probes, supervisor persistence, job schema or completion notifications. Add a conservative Unix-only probe for wait: valid positive PID representable as pid_t, kill(pid, 0)==0 means present; EPERM means present; only ESRCH means absent; all other errors, invalid PID, non-Unix and pid:null mean unknown. Never pass zero, a negative or an overflowed PID to kill. Reuse libc already installed. Existing best-effort pid_liveness is too broad for this contract and must not be repurposed silently.

## Fixed default policy
Enable on all wait surfaces without a new flag. During one invocation, track (pid, started_at) for a persisted running state. Begin a monotonic streak on explicit absence. Require at least three consecutive absence samples AND at least 10 seconds since the first absence. Present/unknown, identity change, created or terminal state resets the streak. No inference from job age, log size, updated_at, connection logs, or missing supervisor records. The grace interval mitigates save latency; it is not proof of termination. PID reuse that probes present intentionally disables detection; do not try to solve process identity with a new persisted format.

Poll at max(1, --poll) seconds. Normal finite deadline wins before new observation detection and is never extended: --until 0 still returns its existing running response. Terminal states always stop absence tracking; terminal plus logs_drained=false keeps waiting for drain as before, even beyond the budget. On a threshold crossing, immediately re-read persisted state and re-probe; return inconsistency only if still running with the same identity and explicit absence. A terminal save seen by that final read wins, using normal drain handling. A save after the final read remains possible: the error explicitly tells clients to query again, never claiming finality.

## Typed response
Create a typed JobObservationInconsistent error in wait with one reusable ErrorResponse renderer. Envelope: ok=false, type=error, error.code=job_observation_inconsistent, retryable=true. Required details: job_id (resolved full ID), root (resolved absolute owning jobs root), state=running, pid (observed positive PID), process_observation=absent. Message states that wait could not reconcile observation with saved state and that a later status/wait can retrieve a saved result. Do not include exit_code, signal or fabricated finish time. CLI expected failure exit 1, MCP normal JSON domain error (not generic transport failure), HTTP 409 Conflict. Retain exact binding and missing-job diagnostics. Advance SCHEMA_VERSION from 0.4 to 0.5 for the new error contract and add the tracked schema changelog entry without changing existing field meanings.

## Mandatory tests

- stale_running_reference: same stale fixture through saved root-bound JSON, conflicting cwd/environment and a second root with same ID; exact root remains selected and both roots unchanged.
- stale_running_mcp: real stdio MCP wait returns typed domain envelope within 25 seconds, no cancellation or notification/state mutation.
- stale_running_http: real loopback isolated serve, GET /wait/<id> returns 409 and domain JSON within 25 seconds; stop only the test-owned server and preserve job bytes.

## Known limitations
The waiter must observe the same host and PID namespace as the supervisor. A shared jobs root from another host/container may produce ESRCH for a live workload and a retryable observation error; document this limitation in the existing user-facing contract docs. Terminal state with logs_drained=false remains a possible indefinite wait and is explicitly outside this repair. The MCP regression must configure an observation budget longer than 10 seconds (use 20 seconds, within its 25-second parent timeout). Re-probe test-owned reaped PIDs before use and re-pick on reuse rather than skipping required coverage.
